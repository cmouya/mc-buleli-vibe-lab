# M5.2 — Sessions, cookies, hashing, login/logout (implementation plan)

**Status:** **Done.** Sessions, cookies, Argon2id (`@node-rs/argon2`), login/logout/GET session. No Golden Reference auth.

**Depends on:** [`docs/m5.2-decisions.md`](m5.2-decisions.md), [ADR-014](architecture-baseline.md#adr-014--m52-sessions-hashed-cookie-token).

## Sequence (C-11)

1. ADR-014 was **Accepted** before this slice.
2. Code: deps, `sessions` `0005`, domain/application/infra/server, tests. Baseline §12: org context from memberships, not the session row.

## Dependencies (C-12)

- `@fastify/cookie`
- Argon2id hasher: **`@node-rs/argon2`** (chosen after Windows smoke)
- `@fastify/rate-limit` — **`POST /api/v1/auth/login` only**; in-memory store OK; Redis deferred

No JWT, Lucia, or Redis.

## Domain / application / infra / server

- **Domain** `src/modules/auth/` (not `identity/` — identity tests forbid `session`): session entity; `isSessionActive`; ports `SessionRepository`, `PasswordHasher`, `TokenDigest`. No Fastify, no Drizzle.
- **Application:** `login`, `logout`, `resolveSession`. Identifier trim + lowercase. Generic invalid credentials. Never log password, hash, or cookie secret.
- **Infra:** Drizzle `sessions`; SHA-256 digest; Argon2id adapter (chosen library). `SCHEMA_SLICE = "m5.2-sessions"`. Migration `0005_*`.
- **Server:** cookie plugin; **in-memory `@fastify/rate-limit` on `POST /api/v1/auth/login`**; `POST /api/v1/auth/logout`; `GET /api/v1/auth/session`. Confirm/generate stay public. 401 `AUTH_INVALID_CREDENTIALS`.

## Login result — session cookie secret boundary

`login` must **not** put the cookie secret on the same object as public user data (no ordinary `rawToken` field that JSON serialization could pick up later).

Return two distinct parts:

- **Safe payload** (same shape as session JSON / AuthContext subset): `userId`, `memberships`, and any non-secret session metadata (`sessionId`, `expiresAt`). This is what HTTP JSON may contain. **AuthContext has no cookie secret.**
- **Internal issued secret** — name it so the boundary is obvious, e.g. `sessionCookieToken` or `issuedSessionSecret`. Typed as a separate return slot (e.g. `{ context, sessionCookieToken }` or a branded/opaque type), **not** a field on AuthContext.

The **server route only** reads that secret to `Set-Cookie` (`learnova.sid`), then drops it. It must **never** appear in JSON, logs, PostgreSQL (only SHA-256 `token_hash`), or AuthContext.

## Password hasher responsibility

- `POST /api/v1/auth/login` **only verifies** a request plaintext password against the stored Argon2id PHC in `user_credentials.secret_hash`. It does not hash a new password for persistence as part of login (rehash-on-login, if any, still writes only a PHC string).
- M5.2 has **no** public registration and **no** credential-creation HTTP route.
- M5.1 `persistPasswordCredential` stays **hash-in**, not plaintext-in.
- Bootstrap/test identities used for login **must** pre-hash via the approved hasher adapter (`@node-rs/argon2`) before persist.
- **No plaintext password is ever persisted.**

## Table `sessions`

- `id` UUID PK
- `user_id` UUID NOT NULL FK `users` RESTRICT
- `token_hash` TEXT NOT NULL UNIQUE
- `expires_at` TIMESTAMPTZ NOT NULL
- `revoked_at` TIMESTAMPTZ NULL
- `created_at` TIMESTAMPTZ NOT NULL default now()
- Index `user_id`. No `organization_id`, IP, UA, `last_seen_at`.

No M4 column changes. No `learners`.

## Cookie

`learnova.sid`: HttpOnly, SameSite=Lax, Path `/`, host-only, Max-Age 24h, Secure in production only.

## Tests

Unit: expiry, revoke, hasher mismatch, identifier normalize, no drizzle in domain/application.

PostgreSQL: hash lookup, unique `token_hash`, missing user FK, revoked/expired inactive.

API: login Set-Cookie HttpOnly; 401; GET session 200/401; logout 204 then 401; JSON has no cookie secret / password / hash; **login rate-limit returns 429 after the configured threshold**.

Schema-boundary: **allow** `sessions`; M4 tables still have no `user_id` / `learner_id` / `organization_id`; identity module still has no `session`.

Regression: typecheck, unit, API, DB, E2E, build.

## Runtime auth composition (M5.2)

`buildApp` **always** registers `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`, and `GET /api/v1/auth/session`. `auth: LoginDependencies` is **required** so routes cannot disappear when a caller omits an optional flag.

Tests inject in-memory identity/session ports (and a hasher). A future process entry (listen / `DATABASE_URL`) will pass Drizzle-backed ports plus `createArgon2idPasswordHasher` and token adapters. That wiring is **not** M5.2: `src/server` must not import Drizzle, and confirm/generate are still not Postgres-backed in `buildApp`.

## Out of scope

JWT, GR login UI, dual-write, Learner, M4 ownership, persist HTTP, Redis, `__Host-`, org-current, password-reset, logout-all HTTP, full tenant isolation (M5.3).
