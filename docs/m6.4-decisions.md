## Context

M6.3 made owned Evidence durable and tenant-safe. The owned write is:

LearnerContext → owned Step proof → `recordQuizEvidence` → `OwnedEvidenceRepository.saveOwned` → relational DB proof → INSERT Evidence.

That write **stops after Evidence persistence**. It does not mutate Step status, Path progress, LearnerState, Mastery, Skills, or Adaptive Path state.

I-05 already exists in domain (`assertEvidenceAllowsCompletion` in `src/modules/evidence/evidence.ts`): a Step may be treated as complete only with **passed Evidence whose `stepId` matches that Step**. `submitAssessment` / the completion adapter apply that law to in-memory Evidence. Golden Reference progression (`src/store.js`) mutates localStorage only.

The tenant-safe owned Evidence flow does **not** consume I-05 after persistence. Owned Evidence is therefore a durable **mutation dead-end**. M6.4 closes that gap with a **derived read-model**. It does not introduce Mastery, LearnerState persistence, Adaptive Path mutation, or Golden Reference dual-write.

## ADR-019

### Status

Accepted

### Context

See above. Goal remains the ownership root. Path/Step/Evidence ownership remains derived. Sessions remain User-only. Confirm/generate remain public.

### Decision

**M6.4** adds **derived tenant-safe owned Step Completion and Path Progress** from **already-persisted owned Evidence**, evaluated under **I-05**. Goal remains the **ownership root**. Completion/Progress ownership is **derived**: Organization → Learner → Goal → Path → Step → Evidence.

**1. Completion is derived, not stored.** A Step is complete **iff** the authorized persisted Evidence set for that Step contains Evidence that satisfies I-05 (`assertEvidenceAllowsCompletion`: matching `stepId` and `passed === true`). Do **not** add `learning_path_steps.status`, `todo`/`current`/`done` columns, `completed`, `completed_at`, or any persisted Step-completion state. **No migration 0008.**

**2. Evidence remains the durable fact.** Do **not** mutate completion when Evidence is POSTed. `POST /api/v1/organizations/:organizationId/goals/:goalId/steps/:stepId/evidence` retains ADR-018 semantics (persist Evidence only). Do **not** extend `persistOwnedEvidence`. Do **not** introduce mixed persist-and-complete use cases.

**3. Read-model, not a completion command.** No `POST/PATCH/PUT .../complete` or status mutation endpoints. Completion is **observed**.

**4. Path Progress is derived aggregation.** `totalSteps` = Steps of the authorized Path. `completedSteps` = count of those Steps that satisfy I-05 from authorized persisted Evidence (count **Steps**, not Evidence rows). `progressPercent` = `0` when `totalSteps = 0`; otherwise the integer percent `Math.round((completedSteps / totalSteps) * 100)` (same empty-path behavior as existing `getProgressPercent` in `src/store.js`). Do not use NaN. Do not use 100 merely because there are no incomplete Steps. Do **not** invent a current Step from this percentage.

**5. No authoritative current-step pointer.** M6.4 does **not** persist `currentStepId` / `nextStepId` / `activeStepId`. DomainLearnerState / GR `getCurrentStep` remain outside this milestone. “First incomplete Step” is **not** LearnerState.

**6. Ownership remains Goal-derived.** Trusted chain: Session → OrganizationContext → LearnerContext. Step proof: Step → Path → Goal with Goal id + `organizationId` + `learnerId`. Path Progress requires the same Path → Goal proof before Steps/Evidence contribute. Client `learnerId` / `organizationId` are **never** authority.

**7. Internal owned Evidence-by-Step query is allowed.** M6.4 **may** add an internal tenant-safe query (name not frozen; security is). Unscoped `EvidenceRepository.getByStepId` is **not** tenant authorization authority. The query must prove Step → Path → Goal plus trusted `organizationId` + `learnerId` before Evidence contributes.

**8. No public Evidence-list product API.** No `GET .../steps/:stepId/evidence` list. Evidence-by-Step is internal. Evidence list/update/delete remain OUT.

**9. HTTP is part of M6.4, after C1+C2 only.** C1 is application/domain/port (no Fastify, no Drizzle). C2 is relational proof. **C3** exposes one **read-only** owned Progress endpoint.

**Accepted route:** `GET /api/v1/organizations/:organizationId/goals/:goalId/path/progress`
Nested under the existing owned Path resource (`GET/POST .../goals/:goalId/path`). Organization-scoped, Goal-owned, Path Progress, no mutation, no client `learnerId`.

**10. HTTP authorization chain:** `learnova.sid` → `resolveSession` → route `organizationId` → `resolveOrganizationContext` → `resolveLearnerContext` → route `goalId` → owned Path/Step proof → owned Evidence query → derived Completion/Progress. Body/query/header tenant fields are not authority.

**11. Non-leaking errors (M6.1–M6.3):** 401 `AUTH_UNAUTHENTICATED` / “Not authenticated”; 403 `ORG_FORBIDDEN` / “Organization access denied”; 404 `RESOURCE_NOT_FOUND` / “Not found” for unknown/inaccessible Goal/Path/Step. Cross-org and same-org wrong Learner indistinguishable from unknown where owned-resource 404 applies. Legacy NULL/NULL Goal fail-closed. Error bodies must not leak `organizationId` / `learnerId`.

**12. Duplicate Evidence remains allowed.** No `UNIQUE(step_id)` on Evidence. Completion is naturally idempotent: **ANY** authorized persisted Evidence satisfying I-05 completes the Step. Multiple passing rows do not make a Step “more complete.” `completedSteps` counts Steps.

**13. Repeated attempts are monotonic attainment.** Failed then passed → complete. Passed then later failed → **remains complete** (at least one I-05-satisfying row). Not latest-attempt status. No revocation/reset in M6.4.

**14. Progress reads are side-effect free.** No inserts/updates of Evidence, Step, Path, Goal, Learner, LearnerState, Skills, Mastery; no adaptive regeneration. No write transaction required merely to read.

**15. No new tenant columns** on Path, Step, or Evidence. No `UNIQUE(goal_id)`.

**16. No migration 0008.** Head remains `0007_m6_1_goal_ownership`.

**17. Golden Reference unchanged.** No dual-write; no GR rewrite of localStorage progression; Playwright GR regression in FINAL VALIDATION.

**18. Mastery is OUT.** I-03 Progress ≠ Mastery. No I-04 implementation.

**19. Skill catalog, Skill ownership, SkillGap persist, LearnerState SQL, currentStep, Adaptive Path, Evidence-driven regeneration, Learner HTTP, and Learner auto-provision are OUT.**

**20. Public confirm and generate remain public.**

**Sessions remain User-only.** Learner creation remains in-process (`persistLearner`). **M6.4 code is not started by this ADR.**

### Alternatives considered

| | Alternative | Disposition |
|---|-------------|-------------|
| A | Persist Step `todo`/`current`/`done` status | **Rejected** for M6.4 — duplicate state, requires 0008, races with Evidence |
| B | Derive completion from persisted Evidence | **Accepted** |
| C | Mutate Evidence POST to complete Step | **Rejected** — violates ADR-018 (Evidence write ≠ Progress mutation) |
| D | Separate completion command (`POST .../complete`) | **Rejected** for M6.4 — stored transition, not derived observation |
| E | Read-only derived Completion/Progress | **Accepted** |
| F | Tenant columns on Step/Evidence | **Rejected** — Goal-derived relational proof remains sufficient |
| G | Internal owned Evidence-by-Step query | **Accepted** as internal capability |
| H | Public Evidence-by-Step list endpoint | **Rejected** for M6.4 |
| I | Include currentStep pointer in M6.4 | **Rejected** — LearnerState / navigation is a later ADR |
| J | Include Mastery / Adaptive Path now | **Rejected** — missing prerequisites; I-03 / I-07 remain later |

### Consequences

**Positive:** no duplicate completion state; no 0008; Evidence remains the durable fact; naturally idempotent derived completion; preserves the M6 Goal-derived ownership chain; minimal Golden Reference risk; clear Progress ≠ Mastery.

**Trade-offs:** Progress requires joins/aggregation; completion is computed, not stored; future revocation needs a new ADR; currentStep remains unresolved by design; Mastery and Adaptive Path remain deferred.

### Security invariants

- User ≠ Learner; Membership ≠ Learner
- Sessions User-only; no session `organizationId` / `learnerId` authority
- OrganizationContext membership-authoritative; LearnerContext server-resolved
- Client `learnerId` / extra-path `organizationId` never authority
- No global `getById` / unscoped `getByStepId` as tenant authority
- Legacy NULL/NULL fail-closed; unknown/inaccessible indistinguishable
- GET Progress has no writes

### Explicit OUT

Persisted Step status; Step status column; `completed_at`; currentStep persistence; LearnerState persistence; Mastery; Skill catalog; Skill ownership; SkillGap persistence; Adaptive Path changes; adaptive regeneration; Learner HTTP; Learner auto-provision; Evidence list HTTP; Evidence update/delete HTTP; completion command; mutation of Evidence POST; progress writes; Path/Goal CRUD expansion; Path/Step/Evidence tenant FKs; `UNIQUE(goal_id)`; `UNIQUE(step_id)` for Evidence; migration 0008; legacy ownership backfill; Golden Reference rewrite; GR dual-write; RBAC; SSO; Program; Cohort.
