# M5.3 — Tenant isolation proof (implementation plan)

**Status:** **Done.** Request-scoped OrganizationContext; `GET /api/v1/organizations/:organizationId/context`; `ORG_FORBIDDEN` → 403. No schema, M4, Learner, or Golden Reference changes.

**Depends on:** [`docs/m5.3-decisions.md`](m5.3-decisions.md), [ADR-015](architecture-baseline.md#adr-015--m53-request-scoped-organization-context).

## Sequence (C-11)

1. ADR-015 **Accepted** (this documentation slice).
2. Future coding: OrganizationContext + proof route + tests. No migration.

## In scope (future implementation)

1. `OrganizationContext` (`userId`, `organizationId`, `role`).
2. `resolveOrganizationContext(AuthContext, organizationId)` — validate requested id against `AuthContext.memberships` only. Existing `listByUserId` / AuthContext memberships are sufficient. No new repository method.
3. Map **`ORG_FORBIDDEN` → HTTP 403** (today unmapped DomainErrors become 400).
4. **`GET /api/v1/organizations/:organizationId/context`** — cookie → `resolveSession` → `resolveOrganizationContext`. No global tenant middleware.
5. Unit and API tenant-isolation proof scenarios (below).
6. Regression and boundary verification.

Server must not query Drizzle. Application must remain Fastify-free. Do not duplicate `resolveSession`.

## Out of scope

- Schema / migrations
- `sessions.organization_id`
- M4 ownership columns
- Learner
- Full RBAC
- Global organization header
- Switch-organization endpoint
- Membership CRUD HTTP
- Protecting confirm/generate
- Golden Reference changes
- Login / logout / cookie / rate-limit changes
- Redis / JWT

## Required proof scenarios (future)

1. User A member of Org A, request A → **200**
2. User A member of Org A, request B → **403**
3. User B member of Org B, request A → **403**
4. User C member of A and B, request A and B → **200** both
5. Authenticated user with zero memberships → **403**
6. No or invalid cookie → **401** `AUTH_UNAUTHENTICATED`
7. Forged or unknown `organizationId` → **403** `ORG_FORBIDDEN`

Also verify:

- JSON has no session token, password, or hash
- Confirm/generate still public
- OpenAPI contains the proof route
- Server remains Drizzle-free
- Application remains Fastify-free
- `sessions` has no `organization_id`
- M4 tables remain without ownership columns
- No Learner
- Golden Reference untouched

## Tests (future)

**Unit:** valid membership; deny invalid/zero; multi-org selection; cannot produce OrganizationContext from client `organizationId` alone.

**API:** scenarios 1–7; secret non-leak; confirm/generate public; OpenAPI path.

**DB:** none if `listByUserId` is unchanged.

**Boundary:** sessions/M4/Learner/server/GR as above.

**Regression:** typecheck, unit, API, DB, E2E, build, `git diff --check`.
