## In scope (executed)

- Learner domain/entity (not User, not Membership, not LearnerState)
- Learner persistence and repository
- `LearnerContext` resolver (User + OrganizationContext → lookup; never trust client `learnerId`)
- Goal `organization_id` / `learner_id` (nullable for legacy M4 rows; required for new tenant-owned writes)
- Tenant-safe Goal repository access (fail closed on unowned rows)
- One minimal tenant-safe Goal persist/read HTTP proof
- Derived Path / Step / Evidence reads through Goal (no independent tenant FKs)
- Unit, API, DB, boundary tests and full regression (typecheck, unit, API, DB, E2E, build, `git diff --check`)

## Out of scope

- Path persistence HTTP
- Evidence persistence HTTP
- Program, Cohort, Mastery
- Invitations / Learner-before-User
- Full RBAC
- Golden Reference modifications (no login, no dual-write)
- Authentication redesign
- `sessions.organization_id` / `sessions.learner_id`
- Protecting confirm/generate
- Fake backfill of M4 Goals

## Migrations (executed)

1. `learners` table
2. `organization_id` FK
3. `user_id` FK
4. UNIQUE `(organization_id, user_id)`
5. nullable `organization_id` on `goals`
6. nullable `learner_id` on `goals`
7. integrity so Goal and Learner belong to the same Organization

Nullable Goal FKs remain **transitional** for existing M4 data, not the desired model for newly tenant-owned Goals.

## Authorization chain (implemented)

`learnova.sid` → `resolveSession` → AuthContext → requested organizationId → `resolveOrganizationContext` → OrganizationContext → `resolveLearnerContext` → LearnerContext → owned Goal / derived-content use case → repository constrained by tenant/learner.

OrganizationContext alone is not sufficient to authorize learning objects.
