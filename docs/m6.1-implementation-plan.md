# M6.1 — Organization-scoped Learner and Goal ownership (implementation plan)

**Status:** **Plan only. Do not execute from this file.** ADR-016 is **Accepted**. **M6 / M6.1 implementation has not started.**

**Depends on:** [`docs/m6.1-decisions.md`](m6.1-decisions.md), [ADR-016](architecture-baseline.md#adr-016--organization-scoped-learner-and-goal-ownership).

## Sequence (C-11)

1. ADR-016 **Accepted** (this documentation slice).
2. Future coding: Learner + LearnerContext + Goal ownership + one tenant-safe Goal persist/read proof. Migration **only** in that coding slice (`db:generate` is not part of this document).

## In scope (future implementation)

- Learner domain/entity (not User, not Membership, not LearnerState)
- Learner persistence and repository
- `LearnerContext` resolver (User + OrganizationContext → lookup; never trust client `learnerId`)
- Goal `organization_id` / `learner_id` (nullable for legacy M4 rows; required for new tenant-owned writes)
- Tenant-safe Goal repository access (fail closed on unowned rows)
- One minimal tenant-safe Goal persist/read HTTP proof
- Unit, API, DB, boundary tests and full regression (typecheck, unit, API, DB, E2E, build, `git diff --check`)

## Out of scope

- Path persistence HTTP
- Evidence persistence HTTP
- Program, Cohort, Mastery
- Invitations / Learner-before-User
- Full RBAC
- Golden Reference modifications (no login, no dual-write)
- Authentication redesign
- `sessions.organization_id` / `sessions.learner_id`
- Protecting confirm/generate
- Fake backfill of M4 Goals

## Future migration (do not generate now)

Approximate contents when M6.1 is coded:

1. `learners` table
2. `organization_id` FK
3. `user_id` FK
4. UNIQUE `(organization_id, user_id)`
5. nullable `organization_id` on `goals`
6. nullable `learner_id` on `goals`
7. integrity so Goal and Learner belong to the same Organization

Nullable Goal FKs are **transitional** for existing M4 data, not the desired model for newly tenant-owned Goals.

## Authorization chain (future)

`learnova.sid` → `resolveSession` → AuthContext → requested organizationId → `resolveOrganizationContext` → OrganizationContext → `resolveLearnerContext` → LearnerContext → owned Goal use case → repository constrained by tenant/learner.

OrganizationContext alone is not sufficient to authorize learning objects.
