## Ownership chain

- Goal remains the **ownership root** (`organization_id` + `learner_id`).
- Path ownership is derived through Goal (`learning_paths.goal_id`).
- Step ownership is derived through Step → Path → Goal.
- Evidence ownership is derived through Evidence → Step → Path → Goal.
- No `organization_id` / `learner_id` on Path, Step, or Evidence.

## Trusted authorization sources

`learnova.sid` → `resolveSession` → requested `organizationId` → `resolveOrganizationContext` (membership-authoritative) → `resolveLearnerContext` (server-resolved; client `learnerId` is never authority) → prove Step belongs to a Path whose Goal matches `goalId` + `organizationId` + `learnerId` → persist Evidence under that Step.

Route `goalId` / `stepId` are requested identifiers, not proof of ownership. Body/query/header `organizationId`, `learnerId`, `ownerId`, `tenantId`, `goalId`, and `stepId` never become authorization authority.

## Non-leaking semantics

Unknown Goal, unknown Step, Step belonging to another Goal, cross-org, same-org wrong Learner, and legacy NULL/NULL Goal chains share a **generic not-found** denial. Do not expose `organizationId` or `learnerId` in error bodies.

## Data / migration
